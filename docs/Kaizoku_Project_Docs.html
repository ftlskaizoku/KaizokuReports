What This App Does

A private daily market intelligence app. The MT5 EA feeds D1 candlestick data from your broker for UK100, DE30, XAUUSD, and USOIL. The server classifies each candle every night, generates a written report with bias and key levels, and sends a push notification to all four users. Users can view charts and reports from any device — phone or desktop — through an installable PWA.

What Each Part Does

1

MT5 EA — Kaizoku_DataFeeder.mq5

Runs inside MetaTrader 5 on your broker connection. Pushes historical D1 candles on first run, then sends each new closed daily candle automatically. Uses your Railway URL + API key to authenticate every request.

2

Railway Server (Node.js + Express)

Receives candle data from the EA, stores it in PostgreSQL. Every night at 22:15 UTC it classifies candles, at 22:20 refreshes statistics, at 22:30 generates reports and fires push notifications.

3

PWA Frontend

Served by the same Node server. Installable on iPhone, Android, and desktop Chrome/Edge. Shows a candlestick chart page per symbol (using TradingView Lightweight Charts) and a Daily Reports page with candle classification, bias, key levels, and the written analysis.

4

Push Notifications

After the report is generated each night, a Web Push notification is sent to every subscribed device. Tapping it opens the app straight to the report. Works on Android and desktop. Safari/iOS requires iOS 16.4+ with the app installed to home screen.

🔧 Deployment Fix APPLIED

✓ Fix Applied — Server Will Now Start
pushNotifications.js

The crash was caused by web-push throwing an error at module load time because VAPID_EMAIL was not yet set in Railway Variables. The fix moves VAPID configuration to a lazy initialiser — it only runs when push notifications are first used, not at startup. The server now starts cleanly even if VAPID keys are missing.

What the log said

// Error at line 7 of pushNotifications.js: Error: No subject set in vapidDetails.subject. at Object.validateSubject (web-push/src/vapid-helper.js:70) at Object.<anonymous> (services/pushNotifications.js:7) // Root cause: // webpush.setVapidDetails() was called immediately at module load. // If VAPID_EMAIL is not set, web-push throws and crashes the whole process.

What was changed

// BEFORE — crashes on startup if env vars not set webpush.setVapidDetails( process.env.VAPID_EMAIL, // throws if undefined process.env.VAPID_PUBLIC_KEY, process.env.VAPID_PRIVATE_KEY ); // AFTER — lazy init, only runs when actually sending a notification function ensureVapid() { if (vapidConfigured) return true; const { VAPID_EMAIL, VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY } = process.env; if (!VAPID_EMAIL || !VAPID_PUBLIC_KEY || !VAPID_PRIVATE_KEY) { console.warn('VAPID keys not set — push disabled until configured.'); return false; // server keeps running fine } webpush.setVapidDetails(VAPID_EMAIL, VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY); vapidConfigured = true; return true; }
Push notifications still work

VAPID is still fully functional — it configures itself the first time a notification is actually sent. Just add the three VAPID variables to Railway and push will work on the next report cycle.

Generating VAPID keys (one-time)

# Run this once locally in your project folder node -e "const wp=require('web-push'); const k=wp.generateVAPIDKeys(); console.log('VAPID_PUBLIC_KEY='+k.publicKey); console.log('VAPID_PRIVATE_KEY='+k.privateKey);" # Then paste the output into Railway → Variables

EA Push Format

The EA sends candles as a JSON array. The server accepts 1 to 5,000 candles per request:

[ { "symbol": "DE30", "date": "2025-04-24", "open": 24038.0, "high": 24055.8, "low": 24006.1, "close": 24023.8, "volume": 12345 }, // ... more candles ]

Database Schema

Five tables in PostgreSQL. Created automatically on first startup via db/schema.sql.

candles — core raw data

ColumnTypeDescription

ColumnTypeDescription
candle_typeTEXTstrong_bullish, pin_bar, doji, engulfing, etc.

d1_biasTEXTbullish / bearish / neutral
bias_confidenceNUMERICProbability % based on historical stats

next_day_directionTEXTFilled next session — what actually happened

daily_reports / pattern_stats / users / push_subscriptions

daily_reports — one report row per symbol per day with full narrative text, key levels JSON, and bias. pattern_stats — aggregated win rates per pattern type, rebuilt nightly. users — the 4 accounts with hashed passwords. push_subscriptions — one row per subscribed browser/device per user.

Nightly Schedule

Four jobs run automatically Monday–Friday via node-cron. All times UTC.

22:00
D1 candles close (broker time)
The EA detects the new bar and immediately pushes the closed candle to /api/ea/push
22:15
Candle Classification Job
Classifies latest D1 bar for all 4 symbols · Updates yesterday's outcome · Writes to candle_analysis
22:20
Pattern Stats Refresh
Aggregates all candle_analysis history into pattern_stats — win rates, outcome percentages
22:30
Report Generation + Push Notifications
Builds written report for each symbol · Upserts into daily_reports · Sends Web Push to all devices
Broker timezone note

Some brokers close D1 at 22:00 UTC, others at 23:00 or 00:00. If your broker uses a different close time, adjust the cron times in services/scheduler.js. The cron strings follow standard syntax: '15 22 * * 1-5' = 22:15 UTC Monday–Friday.

MT5 Setup — IMPORTANT

MT5 blocks all internet requests by default. You must whitelist the Railway URL:

1

Allow WebRequest in MT5

Go to Tools → Options → Expert Advisors. Check "Allow WebRequest for listed URL". Add: https://your-app.railway.app

2

Compile the EA

Copy Kaizoku_DataFeeder.mq5 to %APPDATA%/MetaQuotes/Terminal/[ID]/MQL5/Experts/. In MT5 Navigator panel, right-click → Compile. Green checkmark = success.

3

Attach to any chart

Drag the EA onto any chart. Set InpServerURL and InpApiKey in the inputs. Enable "Allow live trading". The EA runs independently of the chart's symbol.

4

Verify connection

Check the Experts log tab in MT5 — you should see "Server connection OK" and "History backfill complete". Then verify on Railway: GET /api/ea/status returns symbol counts.

Railway Deploy Guide Step by Step

1

Create GitHub repo

Extract the zip. Create a new private repo on GitHub named kaizoku-reports. Then push:

cd kaizoku-reports git init git add . git commit -m "initial commit" git branch -M main git remote add origin https://github.com/YOUR_USERNAME/kaizoku-reports.git git push -u origin main
2

Create Railway project

Go to railway.com/dashboard → New Project → Deploy from GitHub repo → select kaizoku-reports. Railway auto-detects Node.js and deploys.

3

Add PostgreSQL

In your Railway project → click + New → Database → Add PostgreSQL. Railway auto-sets DATABASE_URL — nothing else needed. The schema creates itself on first boot.

4

Set environment variables

In your Railway service → Variables tab → add all variables. See the Environment Variables section for the full list.

5

Create users (one-time)

Once deployed, run this command with your actual Railway URL and API key:

curl -X POST https://your-app.railway.app/api/auth/setup \ -H "Content-Type: application/json" \ -d '{ "setup_key": "YOUR_EA_API_KEY", "users": [ {"username":"you", "password":"yourpass", "display_name":"Your Name", "role":"admin"}, {"username":"friend1", "password":"pass1", "display_name":"Friend 1"}, {"username":"friend2", "password":"pass2", "display_name":"Friend 2"}, {"username":"friend3", "password":"pass3", "display_name":"Friend 3"} ] }'
6

Configure and start the EA

Set up Kaizoku_DataFeeder.mq5 in MT5 with your Railway URL and EA API key. The first run will backfill history automatically. Check the EA log and /api/ea/status to confirm data is arriving.

7

Share the URL

Railway gives you a URL like kaizoku-reports-production.railway.app. Send it to your 3 friends. They open it, log in with their credentials, and install it as a PWA from Settings.
